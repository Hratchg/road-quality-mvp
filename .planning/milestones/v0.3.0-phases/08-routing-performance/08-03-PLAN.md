### Why pgr_dijkstra × K instead of pgr_ksp

Live measurement (08-PERF-NUMBERS.md, direct psql probe with statement_timeout=20s):

| OD pair | K | Filtered edges | Wall clock | Outcome |
|---------|---|----------------|------------|---------|
| DTLA core → Echo Park | 1 | 10,006 | 0.40 s | OK (24 ksp rows) |
| DTLA core → Echo Park | 3 | 10,006 | 20.00+ s | TIMEOUT |
| DTLA core → Echo Park | 5 (production) | 10,006 | 12.00 s | TIMEOUT |

K=1 finishes in 0.4s on the same 10k-edge subgraph that K=3 cannot complete in 20s. Yen's algorithm (which is what `pgr_ksp` runs) rebuilds the graph state per iteration; on dense urban grids many candidate paths share long stretches and Yen's spurious-path enumeration explodes super-linearly. `pgr_dijkstra` is plain single-source-shortest-path with `O(E log V)` complexity. Calling it K times with edge-weight perturbation between calls (so each subsequent run finds a different path) is `O(K × E log V)` — strictly linear in K. RESEARCH §6 explicitly lists this as the "industry-standard k-shortest-paths approach used by OSRM, Valhalla, etc." and the documented fallback when pgr_ksp's K=5 is too slow.

CON-route-selection-algorithm locks "K=5". The locked surface is the OUTPUT contract — five candidate paths fed into the time-budget-filter / fastest-fallback-with-warning Python logic. The algorithm that produces those five paths is implementation choice. RESEARCH §2 originally rejected this option for "semantics drift" — but that was BEFORE measurement showed pgr_ksp K=5 doesn't actually complete on dense graphs. Drift is moot when the chosen algorithm doesn't terminate.

### Edge-weight perturbation: CASE WHEN over a parameter-bound edge-ID array

Two patterns considered:

| Pattern | Pros | Cons | Picked? |
|---------|------|------|---------|
| (a) Temp table `(edge_id, multiplier)` joined into edges_sql | Cleaner separation; reusable for cost adjustments | Extra DDL per iteration; cleanup churn (Pitfall D); two more `cur.execute()` per K iteration; pgr_dijkstra's SPI inner SQL needs to read both `rq_filtered_edges` AND the override table | NO |
| (b) `CASE WHEN id = ANY(%s) THEN cost * %s ELSE cost END` inside the inner edges_sql | Single SQL string; one `cur.execute()` per K iteration; psycopg2 binds the BIGINT[] array natively; no DDL between iterations | The inner SQL string is slightly longer | YES |

Pattern (b) wins. psycopg2's pyformat binding handles `list[int]` parameters by converting to a PostgreSQL `BIGINT[]` literal; the `id = ANY(%s)` predicate is index-friendly and short-circuits when the array is empty (first iteration). RESEARCH §12 already establishes the named-parameter pattern for this file (`%(o_lon)s` etc.); this extends it to the dijkstra inner SQL.

The inner `edges_sql` for pgr_dijkstra:

```sql
SELECT
    id,
    source,
    target,
    CASE WHEN id = ANY(%(blocked)s::bigint[]) THEN cost * %(penalty)s ELSE cost END AS cost
FROM (
    SELECT id, source, target, travel_time_s AS cost FROM <edges_table>
) AS e
```

The outer `pgr_dijkstra` call:

```sql
SELECT path_id, seq, edge, cost
FROM pgr_dijkstra(
    %(inner_sql)s,
    %(origin)s, %(dest)s, directed := false
)
WHERE edge != -1
```

Wait — `pgr_dijkstra` returns columns `(seq, path_seq, node, edge, cost, agg_cost)`, NOT `path_id, seq, edge, cost`. The helper synthesizes a `path_id` per iteration (1..K) and emits rows in the pgr_ksp shape so the existing path-grouping code at routing.py:130+ keeps working unchanged. The renamed columns are documented in pgRouting 3.6: https://docs.pgrouting.org/3.6/en/pgr_dijkstra.html

### Helper signature and pseudocode

```python
import psycopg2

KSP_VIA_DIJKSTRA_INNER_SQL = (
    "SELECT id, source, target, "
    "CASE WHEN id = ANY(ARRAY[{blocked_csv}]::bigint[]) "
    "THEN cost * {penalty} ELSE cost END AS cost "
    "FROM (SELECT id, source, target, travel_time_s AS cost FROM {edges_table}) AS e"
)

# DO NOT use {blocked_csv} or {penalty} as Python format() / f-string interpolation
# of UNTRUSTED data. blocked_csv comes ONLY from prior pgr_dijkstra results
# (BIGINT edge IDs from the database itself, not user input). penalty is a
# module constant. edges_table is hardcoded ('rq_filtered_edges' or
# 'road_segments') — operator-controlled, never user-controlled. T-08-03b-01.

PGR_DIJKSTRA_OUTER_SQL = """
    SELECT seq, edge, cost
    FROM pgr_dijkstra(
        %(inner_sql)s,
        %(origin)s, %(dest)s, directed := false
    )
    WHERE edge != -1
    ORDER BY seq
"""


def find_k_shortest_via_dijkstra(
    cur,
    origin_node: int,
    dest_node: int,
    k: int = 5,
    edges_table: str = "rq_filtered_edges",
    weight_penalty: float = 1000.0,
) -> list[dict]:
    """Run pgr_dijkstra k times with edge-weight perturbation between iterations.

    Returns a list of row dicts in pgr_ksp output shape:
      [{"path_id": 1, "seq": 1, "edge": 42, "cost": 3.5}, ...]

    Algorithm (Yen's-style edge-weight perturbation):
      1. Run pgr_dijkstra(origin, dest) on the unperturbed graph -> path_1.
      2. Collect path_1's edge IDs into the `blocked` set.
      3. For i in 2..k: run pgr_dijkstra with cost-of-blocked-edges
         multiplied by weight_penalty (so subsequent runs prefer
         alternatives but can still cross blocked edges if no
         alternative exists). Add new path's edges to `blocked`.
      4. If iteration i returns 0 rows, stop early (no more distinct paths).

    Why edge-weight perturbation (not edge removal):
      - Edge removal can leave the graph disconnected for the OD pair,
        returning 0 rows after the first path.
      - Multiplicative penalty (cost * 1000) makes blocked edges
        "expensive but still traversable"; pgr_dijkstra still finds
        a path through them if no cheaper alternative exists.
      - 1000.0 is high enough to dominate any realistic alt-path
        cost difference (LA edges are 1-300s of travel_time_s; 300 * 1000
        = 300000s, which is two orders of magnitude above any plausible
        unperturbed full-route cost).

    Returns empty list if the FIRST pgr_dijkstra returns 0 rows
    (no path between origin and dest in this subgraph). The caller
    is responsible for falling back to a wider subgraph or full graph.
    """
    rows: list[dict] = []
    blocked: list[int] = []

    for path_id in range(1, k + 1):
        # Build the inner SQL by SAFELY substituting only operator/system-controlled
        # values: edges_table (hardcoded by the caller), the blocked-edge
        # array literal (built from BIGINT IDs the DB itself returned in
        # prior iterations -- never user input), and the penalty (module
        # constant float).
        blocked_literal = ",".join(str(int(e)) for e in blocked)  # int() coerces; safe
        inner_sql = (
            f"SELECT id, source, target, "
            f"CASE WHEN id = ANY(ARRAY[{blocked_literal}]::bigint[]) "
            f"THEN cost * {float(weight_penalty)} ELSE cost END AS cost "
            f"FROM (SELECT id, source, target, travel_time_s AS cost FROM {edges_table}) AS e"
        )
        cur.execute(
            PGR_DIJKSTRA_OUTER_SQL,
            {"inner_sql": inner_sql, "origin": origin_node, "dest": dest_node},
        )
        path_rows = cur.fetchall()

        if not path_rows:
            # No path on this iteration. If it's the FIRST iteration, the
            # subgraph has no OD path -> return empty so caller can widen.
            # If it's a LATER iteration, we just ran out of distinct
            # alternatives -> return what we have so far.
            break

        for r in path_rows:
            rows.append(
                {
                    "path_id": path_id,
                    "seq": r["seq"],
                    "edge": r["edge"],
                    "cost": r["cost"],
                }
            )
            blocked.append(int(r["edge"]))

    return rows
```

CRITICAL: `blocked_literal` is built from Python `int()` calls over BIGINT edge IDs returned by `pgr_dijkstra` itself. There is NO user-input pathway into that string. The f-string interpolation is safe under T-08-03b-01 because the inputs are typed-and-coerced ints from the DB. Ditto `float(weight_penalty)` (module constant) and `edges_table` (hardcoded caller-side). DO NOT extend this pattern to ANY user-supplied value.

For an EVEN safer alternative, the executor MAY use parameter binding via `psycopg2.sql.SQL` and `psycopg2.sql.Identifier` for `edges_table` and a separately-bound array param for `blocked`. The plan body's f-string approach is the simpler one and is verified safe by static analysis (the `int()` coercion in the comprehension) — pick whichever the executor finds cleaner without changing the algorithmic semantics.

### Control flow in find_route() — 3-attempt fallback with QueryCanceled handling

The new shape replacing the second `with get_connection() as conn:` block (currently lines 117-155 in the post-revert routing.py):

```python
import psycopg2

# ...

with get_connection() as conn:
    with conn.cursor() as cur:
        # 1. Snap origin/dest to vertex IDs (UNCHANGED)
        cur.execute(SNAP_NODE_SQL, (req.origin.lon, req.origin.lat))
        origin_node = cur.fetchone()["id"]
        cur.execute(SNAP_NODE_SQL, (req.destination.lon, req.destination.lat))
        dest_node = cur.fetchone()["id"]

        ksp_rows: list[dict] = []
        bbox_params = {
            "o_lon": req.origin.lon, "o_lat": req.origin.lat,
            "d_lon": req.destination.lon, "d_lat": req.destination.lat,
            "buf": ROUTE_FILTER_BUFFER_DEG,
        }

        # Attempt 1: filter at default buffer + dijkstra K=5 with perturbation.
        try:
            cur.execute(CREATE_FILTERED_EDGES_SQL, bbox_params)
            cur.execute(INDEX_FILTERED_EDGES_SQL)
            ksp_rows = find_k_shortest_via_dijkstra(
                cur, origin_node, dest_node, k=K,
                edges_table="rq_filtered_edges",
            )
        except psycopg2.errors.QueryCanceled:
            # 12s statement_timeout fired. Reset transaction state so subsequent
            # attempts on the same connection can proceed.
            conn.rollback()
            ksp_rows = []

        # Attempt 2: widen the buffer, retry. Triggers on either empty result
        # OR timeout from attempt 1.
        if not ksp_rows:
            try:
                # The temp table from attempt 1 may or may not exist depending
                # on whether attempt 1 timed out before/after the CREATE.
                # IF EXISTS guards both cases.
                cur.execute("DROP TABLE IF EXISTS rq_filtered_edges")
                wide_params = {
                    **bbox_params,
                    "buf": ROUTE_FILTER_BUFFER_DEG * ROUTE_FILTER_WIDEN_FACTOR,
                }
                cur.execute(CREATE_FILTERED_EDGES_SQL, wide_params)
                cur.execute(INDEX_FILTERED_EDGES_SQL)
                ksp_rows = find_k_shortest_via_dijkstra(
                    cur, origin_node, dest_node, k=K,
                    edges_table="rq_filtered_edges",
                )
            except psycopg2.errors.QueryCanceled:
                conn.rollback()
                ksp_rows = []

        # Attempt 3: full-graph fallback. Triggers on either empty result
        # OR timeout from attempt 2. Last-resort correctness guarantee --
        # a slow response is better than a 500.
        if not ksp_rows:
            try:
                cur.execute("DROP TABLE IF EXISTS rq_filtered_edges")
                ksp_rows = find_k_shortest_via_dijkstra(
                    cur, origin_node, dest_node, k=K,
                    edges_table="road_segments",
                )
            except psycopg2.errors.QueryCanceled:
                conn.rollback()
                ksp_rows = []

        # 5. Group by path_id (UNCHANGED — existing logic from routing.py:130+)
        paths: dict[int, list[int]] = {}
        for row in ksp_rows:
            paths.setdefault(row["path_id"], []).append(row["edge"])

        if not paths:
            return RouteResponse(
                fastest_route=RouteInfo(
                    geojson={"type": "LineString", "coordinates": []},
                    total_time_s=0,
                    total_cost=0,
                ),
                best_route=RouteInfo(
                    geojson={"type": "LineString", "coordinates": []},
                    total_time_s=0,
                    total_cost=0,
                ),
                warning="No route found between these points",
                per_segment_metrics=[],
            )

        # Fetch all segment data (UNCHANGED)
        all_edge_ids = list({eid for edges in paths.values() for eid in edges})
        cur.execute(SEGMENTS_BY_IDS_SQL, (all_edge_ids,))
        seg_rows = cur.fetchall()
        seg_data = {row["id"]: row for row in seg_rows}
```

KEY contracts:
- All SQL runs on the SAME `conn` and SAME `cur` so the temp table is visible to the subsequent dijkstra calls (RESEARCH §5 + Pitfall C).
- `DROP TABLE IF EXISTS rq_filtered_edges` between attempts (note: `IF EXISTS` differs from old plan which used unconditional DROP — necessary because a QueryCanceled mid-CREATE may or may not have left the table behind, and we don't want to compound failures).
- `conn.rollback()` after every QueryCanceled — this resets the transaction's failed-state flag. Without rollback, the next `cur.execute()` raises `psycopg2.errors.InTransaction` instead of running.
- The 12s `SET LOCAL statement_timeout` from db.py:97-98 caps EACH `cur.execute()` independently. Worst-case: 3 × 12s = 36s before the response, but only if all three attempts time out at exactly 12s — which is a degenerate case (attempt 3 is the original baseline that completes in ≤90s without filter, but the time-out shortens it to 12s minimum). In practice attempt 1 finishes in well under 1s when K is linear-cost.
- Audit-log insert (lines 105-110) and cache read (lines 112-115) are UNCHANGED — they live in a separate `with get_connection()` block that commits before the routing block runs.

```python
# inside find_k_shortest_via_dijkstra(); see that function's docstring for
# why edge-weight perturbation runs Yen's-style algorithm linear in K

    SELECT seq, edge, cost

# Penalty multiplier applied to edges from previously-found paths. Multiplicative
# (not additive) so it dominates any realistic alt-path cost difference. 1000x
# means a blocked 300-second edge becomes a 300000-second edge -- two orders of
# magnitude above any plausible full-route cost in LA. Override via env var if
# operator wants tighter or looser path-diversity behavior.
DIJKSTRA_BLOCKED_EDGE_PENALTY = float(
    os.environ.get("DIJKSTRA_BLOCKED_EDGE_PENALTY", "1000.0")
)


def find_k_shortest_via_dijkstra(
    cur,
    origin_node: int,
    dest_node: int,
    k: int = 5,
    edges_table: str = "rq_filtered_edges",
    weight_penalty: float | None = None,
) -> list[dict]:
    """Run pgr_dijkstra k times with edge-weight perturbation between iterations.

    Returns a list of row dicts in pgr_ksp output shape:
      [{"path_id": 1, "seq": 1, "edge": 42, "cost": 3.5}, ...]

    Why this exists (Phase 8 second-replan):
      pgr_ksp with K=5 explodes super-linearly on dense urban subgraphs
      (08-PERF-NUMBERS.md: K=1 = 0.4s, K=3 = 20s+, K=5 = 12s timeout, all
      on the same 10k-edge subgraph). pgr_dijkstra called K times with
      edge-weight perturbation between calls is linear in K -- the
      industry-standard k-shortest-paths approach used by OSRM and Valhalla.
      Same K=5 candidate paths, same row shape, much better complexity.

    Algorithm (Yen's-style edge-weight perturbation):
      1. Run pgr_dijkstra(origin, dest) on the unperturbed graph -> path_1.
      2. Collect path_1's edge IDs into the `blocked` set.
      3. For i in 2..k: run pgr_dijkstra with cost-of-blocked-edges
         multiplied by weight_penalty (so subsequent runs prefer
         alternatives but can still cross blocked edges if no
         alternative exists). Add new path's edges to `blocked`.
      4. If iteration i returns 0 rows, stop early (no more distinct paths).

    Why edge-weight perturbation (not edge removal):
      - Edge removal can leave the graph disconnected for the OD pair,
        returning 0 rows after the first path.
      - Multiplicative penalty (cost * 1000) makes blocked edges
        "expensive but still traversable"; pgr_dijkstra still finds
        a path through them if no cheaper alternative exists.

    Args:
        cur: an open psycopg2 cursor on a connection that has already
            run CREATE TEMP TABLE for `edges_table` (when edges_table
            != "road_segments"). The cursor MUST share the transaction
            with the temp-table creation -- see Pitfall C in 08-RESEARCH.md.
        origin_node: vertex ID returned by SNAP_NODE_SQL for the origin.
        dest_node: vertex ID returned by SNAP_NODE_SQL for the destination.
        k: number of K-shortest paths to find. Default 5
            (CON-route-selection-algorithm).
        edges_table: name of the table to read edges from. "rq_filtered_edges"
            (the bbox-filtered temp table from Plan 08-02) or "road_segments"
            (full-graph fallback). Caller-controlled, never user-supplied --
            do NOT pass user input here (T-08-03b-01).
        weight_penalty: multiplier applied to edges in already-found paths.
            None = read DIJKSTRA_BLOCKED_EDGE_PENALTY (1000.0 default).

    Returns:
        list of dicts with keys {"path_id", "seq", "edge", "cost"}. Empty
        list when iteration 1 returns 0 rows (caller falls back). Up to
        k * <path-length> rows in the happy path.

    Security (T-08-03b-01):
        The inner SQL string interpolates ONLY system-controlled values:
        - `edges_table` is a hardcoded caller-side string (caller is
          find_route() in this same module).
        - `blocked_literal` is a comma-separated list of int()-coerced
          edge IDs returned BY pgr_dijkstra ITSELF in prior iterations.
          User input never reaches this string.
        - `weight_penalty` is float()-coerced from a module constant.
        psycopg2 still parameter-binds origin / dest via %(origin)s /
        %(dest)s in the OUTER SQL.
    """
    if weight_penalty is None:
        weight_penalty = DIJKSTRA_BLOCKED_EDGE_PENALTY

    rows: list[dict] = []
    blocked: list[int] = []

    for path_id in range(1, k + 1):
        # int() coercion prevents any non-integer slipping through.
        # blocked items are always BIGINT edge IDs from the DB.
        blocked_literal = ",".join(str(int(e)) for e in blocked)
        inner_sql = (
            f"SELECT id, source, target, "
            f"CASE WHEN id = ANY(ARRAY[{blocked_literal}]::bigint[]) "
            f"THEN cost * {float(weight_penalty)} ELSE cost END AS cost "
            f"FROM (SELECT id, source, target, travel_time_s AS cost "
            f"FROM {edges_table}) AS e"
        )
        cur.execute(
            PGR_DIJKSTRA_OUTER_SQL,
            {"inner_sql": inner_sql, "origin": origin_node, "dest": dest_node},
        )
        path_rows = cur.fetchall()

        if not path_rows:
            # Iteration 1 with no rows -> no path in this subgraph; caller
            # must widen or fall back. Iterations 2..k with no rows ->
            # we just ran out of distinct alternatives; return what we have.
            break

        for r in path_rows:
            rows.append(
                {
                    "path_id": path_id,
                    "seq": r["seq"],
                    "edge": r["edge"],
                    "cost": r["cost"],
                }
            )
            blocked.append(int(r["edge"]))

    return rows
```
